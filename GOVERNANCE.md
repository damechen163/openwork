# Governance

OpenWork uses a maintainer-led, issue-driven model during the alpha phase.

- Maintainers set release scope, merge changes, manage security reports, and enforce
  licensing and compatibility gates.
- Architecture changes require a `needs-design` issue and an ADR.
- Single-maintainer development uses CI, self-review, and issue acceptance criteria;
  no review is fabricated. Human review rules will be strengthened as the team grows.
- Community code remains usable for self-hosting. Commercial hosted or partner products
  must live outside this repository and integrate through public extension points.

Decisions should optimize reliable deployment and maintenance for a real client company,
not feature-count marketing.
